# 索引优化

## 基本知识

合理设置所用会对`数据库性能数据库性能`带来很大提升。

### 测试数据

为了演示索引需要添加些测试数据，下面时添加学生数据的存储过程代码。如果你已经有测试数据可以省掉这一步

```sql
-- 1. 临时修改语句结束符为 $$，避免存储过程内部的 ; 提前终止定义
DELIMITER $$

-- 2. 创建存储过程 add_stus，参数 num 是输入型整数（表示要插入的记录数）
CREATE PROCEDURE add_stus(IN num int)
-- 3. 存储过程逻辑开始标记
BEGIN
    -- 4. 声明局部变量 i，整数类型，默认值 0（循环计数器）
    DECLARE i int DEFAULT 0;
    -- 5. 声明局部变量 _birthday，datetime 类型（存储随机生成的生日）
    DECLARE _birthday datetime;

    -- 6. WHILE 循环：当传入的 num 大于计数器 i 时，执行循环体
    WHILE num>i DO
        -- 7. 生成随机生日：当前时间往前随机减 0~999 天
        SET _birthday  = date_sub(now(),INTERVAL floor(RAND()*1000) day);
        
        -- 8. 向 stu 表插入一条模拟学生数据
        INSERT INTO stu SET
        sname = concat(left(md5(RAND()),5),'后盾人向军'),  -- 姓名：随机5位字符 + 固定后缀
        class_id =1+FLOOR( RAND()*100000),                 -- 班级ID：1~100000 随机整数
        birthday = _birthday ,                             -- 生日：上面生成的随机日期
        sex = 1+FLOOR(RAND()*2 );                          -- 性别：1 或 2（随机）

        -- 9. 计数器 i 加 1，避免死循环
        SET i= i+1;
    -- 10. WHILE 循环结束标记
    END WHILE;
-- 11. 存储过程逻辑结束标记
END
$$
-- 12. 改回 MySQL 默认的语句结束符 ;
DELIMITER ;
```

调用存储过程添加五十万条记录

```sql
call add_stus(500000)
```

### 基础思路

<strong>选择合理范围内最小的</strong>

我们应该选择最小的数据范围，因为这样可以大大减少磁盘空间及磁盘 `I/O读写开销`，减少内存占用，减少`CPU`的占用率

<strong>选择相对简单的数据类型</strong>

数字类型型对字符串类型要简单的多，尤其是在比较运算时，所以我们应该选择最简单的数据类型，比如说在保存时间时，因为 PHP 可以良好的处理 LINUX 时间戳所哟我们可以将日期存为 int(10) 要方便、合适、快速的多。

### 字符串

字符串数据类型是一个万能数据类型，可以存储数值、字符串等。

保存数值类型最好不要用`字符串数据类型`，这样存储的空间显然时会更大，而且在排序时字符串的'9'是大于`22`的.如果进行运算时`mysql`会将字符串转换为`数值类型`，这种转换是不会走索引的。

如果明确数据在一个完整的集合中如`男，女`，那么可以使用 `set或enum`数据类型，这种数据类型在运算及存储时以数值方式操作，所以效率要比字符串更好，同时空间占用更少

### 数值类型

#### 整数

整数类型很多比如`tinyint，int，smallint，bigint`等，那么我们要根据自己需要存储的数据长度决定使用的类型，同时`tinyint(10)与yinyint(100)`在存储与计算上并无任何差别，区别只是显示层面上，但是我们也要选择适合合适的数据类型长度。可以通过指定`zerofill`属性查看显示时区别

<strong>浮点数与精度数值</strong>

浮点数`floar与double`在存储空间及运行效率上要优于京都数值类型`decimal`,但`float与double`会有舍入错误而`decimal`则可以提供更加准确的小数级精确运算不会有错误产生计算更精确，适用于金融类型数据的存储。

<strong>总结：</strong>

数值数据类型要比字符串执行更快，范围区间晓得额数据类型占用空间更少，处理速度更快，如`tinyint`可以`bigint`要快的多，选择数据类型是要考虑内容长度，比如时保存毫米单位还是米而选择不同的数值类型。

### EXPLAIN

## 索引基础

索引就像一本书的目录一样，我们可以通过一本书的目录，快速的找到需要的页面，但是我们也不能过多的船舰目录页（索引），原因是如果一篇文章删除或修改将改变所有页码的顺序，就需要重新创建目录

```sql
select sname from stu where sname = "张三"
# 如果 sname 使用了索引，上面这个例子就会使用到 sname 索引
```

### 索引弊端

- 创建索引会使查询操作变得更加快速，但是会`降低增加、删除、更新操作的速度`，因为执行这些操作的同时会对索引文件进行`重新排序或更新`
- 创建过多列的索引`会大大增加磁盘空间开销`
- 不要盲目的创建索引，只为查询操作频繁的列创建索引

### 索引类型

| 索引                 | 说明                                |
| -------------------- | ----------------------------------- |
| UNIQUE 唯一索引      | 不可以出现相同的值，可以有 NULL 值  |
| INDEX 普通索引       | 运行出现相同的索引内容              |
| PRIMARY KEY 主键索引 | 不允许出现相同的值，且不能为 NULL值 |

### 索引维护

为stu 学生表的 sname 字段设置索引

```sql
ALTER TABLE stu ADD INDEX sanme_index(sname)
```

删除索引

```sql
ALTER TABLE stu DROP INDEX sname_index;
```

删除主键索引，首先需要移除`auto_increment`然后删除主键索引

```sql
ALTER TABLE stu MODIFY id int;
ALTER TABLE stu DROP PRIMART KEY;
```

查看表索引

```sql
show index from stu;
```

### 性能分析

索引是加快查询操作的重要手段，如果当发生查询过慢时添加上索引后会发现速度大大改观

#### 普通字段

当没有地表`class_id`字段添加索引时，查找`cid`为  3 的记录会执行全表扫描，性能是最差的

```sql
EXPLAIN SELECT * FROM stu WHERE class_id = 5 limit 1;
```

通过结果的`type=ALL`可以看到执行全表扫描，遍历了一百万条记录


#### 多表操作

子啊使用连接操作多个表时，如果没有添加索引性能会非常差

```sql
explain select * from a join b on a.id = b.id join c on b.ic = c.id;
```

结果中会看到每张表都遍历了所有记录

下面来添加索引

```sql
ALTER TABLE a ADD INDEX id(id);
ALTER TABLE b ADD INDEX id(id);
ALTER TABLE c ADD INDEX id(id);
```

## 字段选择

### 维度思考

- 数据列中不重复值出现的个数，维度的最大值时数据行的数量
- 如数据表中存在 8 行数据`a,b,c,d,a,b,c,d`这个表的维度为4
- 要为维度高的列创建索引
- 性别这样的列不适合创建索引，因为维度过低

### 索引规则

- 对`where,on 或 group by 及 order by`中出现的列使用索引
- 对较小的数据列使用索引，这样会使索引文件更小，同时内存中也可以装载更多的索引键
- 为较长的字符串使用前缀索引
- 不要过多创建索引，除了增加额外的磁盘空间外，对于`DML`操作的速度影响很大

## 前缀与组合

### 前缀索引

大使用 text/长 varchar 字段时创建索引，会造成索引列长度过长，从而生成过大的索引文件影响检索性能。使用前缀索引方式进行索引，可以有效解决这个问题。前缀索引应该控制在一个合适的点，控制在 0.31 黄金值即可。

下面是取前缀索引的计算公式，有时也根据字段保存内容确定，比如标题 100 可以取 30 个字符为索引

```sql
select count(distinct(left(title,10)))/count(*) from news
```

下面为文章表 article 的 title 字段添加 30 个长度的前缀索引

```sql
ALTER TABLE article ADD INDEX title(title(30));
```

### 索引组合

组合索引为是多个字段统一设计索引

- 可以较为每个字段设置索引文件体积更小
- 使用速度优于多个索引操作
- 前面字段没出现，只出现后面字段时不走索引

下面为学生表中的班级字段 class_id 与学生状态 status 设置组合索引

```sql
Alter table stu add index class_id_status(class_id,status);
```

使用 class_id 时会走索引，因为 class_id 在组合索引最前面

```sql
explain select * from stu where class_id =3;
```

只使用 status 字段不会走索引

```sql
explain select * from stu where status =1
```

当 class_id 与 status 字段一起使用时会走索引

```sql
explain select * from stu where status =1 and class_id=5;
```

## 查询优化

### 解析器

Mysql 的解析器非常智能，会对发出的每条 SQL 进行分析，决定是否使用索引或是否进行全表扫描。

下面发送的 SQL 解析器分析后已经清楚不会有任何语句符合操作，所以不会操作任何表或索引

```sql
select * from houdunwang where false
```

### 表达式影响

下面 SQL 语句不会使用索引，因为所有索引列参与了计算

```sql
explain select * from stu where status+1=1;
```

下面 SQL 不会使用索引，因为使用了函数运算，原理与上面相同

```sql
explain select * from stu where left(sname,1)='张三'
```

下面 SQL 不会使用索引，因为索引列是模糊匹配的

```sql
explain select * from stu where sname like '%张三%'
```

下面 SQL 会使用索引，因为不是模糊匹配

```sql
explain select * from stu where sname like '张三%'
```

正则表达式也不会使用索引

```csharp
explain select * from stu where sname regexp '^张三'
```

### 类型比较

相同类型比较时走索引

```sql
explain select * from stu where sname="1";
```

字符串类型使用数值时不走索引

```sql
explain select * from stu where sname=1;
```

### 排序

排序中尽量使用添加索引的列进行

下例使用数据表进行排序

```sql
explain select id from stu order by birthday
```

排序字段为索引列后使用索引表排序

```sql
explain select id from stu order by id ;
```

## 慢查询

当 Mysql 性能下降时，通过开启慢查询来获得哪条 SQL 语句造成的响应过慢进行分析处理。当然开启慢查询会带来 CPU 损耗与日志记录的 IO 开销，所以我们要间断性的打开慢查询日志来查看 Mysql 运行状态。

慢查询能记录下所有执行超过 long_query_time 时间的 SQL 语句, 用于找到执行慢的 SQL, 方便我们对这些 SQL 进行优化。

### 状态查看

查看开启慢查询状态

```sql
show variables like 'slow_query%';

+---------------------+-----------------------------------+
| Variable_name       | Value                             |
+---------------------+-----------------------------------+
| slow_query_log      | OFF                               |
| slow_query_log_file | /var/lib/mysql/homestead-slow.log |
+---------------------+-----------------------------------+
```

查看慢查询设置的时间

```sql
show variables like "long_query_time"

+-----------------+-----------+
| Variable_name   | Value     |
+-----------------+-----------+
| long_query_time | 10.000000 |
+-----------------+-----------+
```

### 运行配置

**会话配置**

通过以下指令开启全局慢查询（如果重起 Mysql 后需要重新执行）

```sql
set global slow_query_log='ON';
```

设置慢查询时间为 1 妙，即超过 1 秒将会被记录到慢查询日志

```sql
set session long_query_time=1;
```

**全局配置**

通过修改配置 mysql 配置文件 my.cnf 来开启全局慢查询配置，在配置文件中修改以下内容

```cobol
slow_query_log = ON
slow_query_log_file = /usr/local/mysql/data/slow.log
long_query_time = 1
```

重起 `MYSQL`服务

```sql
service mysqld restart
```
